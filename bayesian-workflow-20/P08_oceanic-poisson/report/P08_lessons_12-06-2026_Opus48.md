# Lessons Report — Project 08: Oceanic tool kits (Poisson regression)

**Author:** Truong Van Thien, PhD · **Date:** 12-06-2026 · **Model tag:** Opus48

## 1. The concept taught
**Poisson regression** with a **log link**: `total_tools ~ Poisson(exp(linear predictor))`. Two craft
skills — reading a slope as a **multiplicative** effect on the count, and setting the **intercept prior
on the count scale** so it implies plausible tool numbers rather than millions.

## 2. Workflow lessons from this run (with the actual numbers)
1. **Recovery first:** simulating with a = 3.2, b_p = 0.3, b_c = 0.2 recovered all three inside their
   90% HDIs (3.21, 0.303, 0.249); R̂ = 1.00.
2. **The prior must be set on the COUNT scale:** a "harmless" `Normal(0,10)` intercept implies a
   95th-percentile tool count of **~15.6 million**; the chosen `Normal(3,0.5)` implies median **20**,
   95th percentile **45**. You only see this by exponentiating the prior.
3. **The result:** b_p = **+0.398** (94% HDI +0.299..+0.493) → a +1 SD in log-population **multiplies
   expected tools by 1.49×**. Tool kits clearly grow with population.
4. **The interaction is undetermined:** b_pc = **+0.084** (94% HDI **-0.358..+0.503**) straddles 0; the
   population slope is +0.398 (low contact) vs +0.482 (high contact), but n = 10 cannot separate them.
5. **LOO does not support the interaction:** `elpd_diff` = **2.94 ± 2.10** (1.4 SE) favours the simpler
   model — and max Pareto-k̂ = **1.11** with **3/10** bad points (Hawaii and friends), so LOO is
   approximate and `reloo` is the honest fix.
6. **PPC is clean:** mean/max/sd bayes-p = 0.48 / 0.46 / 0.34 — the Poisson fits the central counts and
   the Hawaii extreme without obvious misfit.

## 3. Common mistakes
- **Setting priors on the log scale by habit** (`Normal(0,10)`) — innocuous-looking, catastrophic on the count scale.
- **Over-interpreting the interaction** from n = 10 — the HDI spans both signs.
- **Quoting raw LOO** when 3/10 Pareto-k̂ exceed 0.70; use `reloo` or say "approximate".

# Lessons — Project 06: Overdispersed Counts (Negative-Binomial)

This is the lessons report for the count-GLM project. It records what the project
teaches, the surprises met while building and running it, and how the ideas
generalize to count modeling across the portfolio.

---

## 1. What this project is really about

On the surface it fits a count regression. The real subject is **overdispersion**
and the discipline of **choosing a likelihood family with a quantitative criterion**
rather than by reflex. The Poisson is the default count model in most people's
heads, and it is almost always wrong for real data because it forces
$\operatorname{Var}(y)=\mu$. The Negative-Binomial adds one parameter and fixes
this. The project teaches you to *detect* the problem (var/mean, PPC) and to
*adjudicate* the fix (LOO via `az.compare`).

The eight workflow steps map to artifacts as usual:

1. Data story — `data/generate_data.py` (overdispersed NB counts).
2. Models + priors — `model.py` (both Poisson and NB, log link).
3. Prior predictive — Step 3 cell (heavy-tailed counts).
4. Inference — `model.fit` for both families.
5. Diagnostics — $\hat R$/ESS/divergences (both pass!).
6. Posterior predictive — `plot_ppc` + variance comparison (Poisson fails).
7. Comparison — `az.compare` with LOO (NB wins).
8. Decision — fold-change $e^{\beta_1}$.

Plus SBC (`sbc.py`), prior sensitivity (`prior_sensitivity.py`), and the
Poisson-forced broken notebook.

## 2. Takeaways

### 2.1 Convergence is not adequacy

The most transferable lesson. The Poisson model converges *perfectly* on
overdispersed data — $\hat R=1.00$, healthy ESS, zero divergences. If you stop at
convergence diagnostics you will ship a badly wrong model with a clean bill of
health. Convergence diagnostics interrogate the **sampler**; only posterior
predictive checks and model comparison interrogate the **model**.

### 2.2 Overdispersion is the default, not the exception

For RNA-seq, colony counts, spike trains, accident counts — anything generated by
heterogeneous units — the variance exceeds the mean. The Poisson's
equidispersion is a strong, usually-false assumption. Treat the NB as the baseline
and make the Poisson *earn* its place via LOO. The portable check is the one-liner
`y.var()/y.mean()`: if it is well above 1, the Poisson is already in trouble.

### 2.3 The log link separates mean from variance

A pleasant surprise in the prior-sensitivity analysis: the regression coefficient
$\beta_1$ barely moves as we change the dispersion prior on $\alpha$. The log link
decouples the mean structure from the dispersion structure, so conclusions about
the *effect of $x$* are robust to how we model the *variance*. This is reassuring
and worth telling collaborators: "our estimate of the fold-change does not depend
on the dispersion modeling choices."

### 2.4 LOO turns a visual impression into a defensible decision

The PPC *shows* the Poisson predictions are too tight; `az.compare` *proves* the
NB predicts held-out data better, with `elpd_diff` many `dse` from zero. The PPC
builds intuition; LOO supplies the number you put in a report. Both, not either.

### 2.5 Dispersion parameters are weakly identified — and SBC confirms honesty

$\alpha$ is the hardest parameter to pin down, especially at small $N$. The SBC
rank histogram for $\alpha$ being flat tells us the posterior is *honest* about
that difficulty rather than over-confident — exactly what we want from a parameter
that the data only weakly constrain.

## 3. Surprises & failure modes encountered while building

### 3.1 The Poisson looked great until the PPC

While building, the Poisson fit produced clean diagnostics and a sensible-looking
$\beta_1$. It was only the variance comparison (Poisson predicted ~70 vs observed
~150, while the NB predicted ~280) that exposed the problem. This is the entire
pedagogical point, encountered live.

### 3.2 The NB prior tail can blow up the simulation

In SBC, drawing $\alpha$ and $\beta_0$ from the full model-default priors
occasionally produced enormous implied means (exponentiation is unforgiving),
yielding slow, ill-conditioned fits. The fix was to use a sensibly constrained
prior *for SBC only* — SBC validates the inference machinery over a representative
parameter slice, not the entire pathological prior tail. This is a standard SBC
practicality, now documented in `SBC_REPORT.md`.

### 3.3 An over-confident dispersion prior reintroduces the Poisson pathology

In prior sensitivity, $\text{Gamma}(20,1)$ — which essentially asserts low
overdispersion — pulled the $\alpha$ posterior away from the truth toward
Poisson-like behavior. A reminder that you can sneak the very misspecification you
were trying to avoid back in through an over-confident prior. Prefer a flexible,
heavy-tailed dispersion prior.

### 3.4 The (mu, alpha) -> (r, p) conversion is a quiet trap

numpy's `negative_binomial` wants `(n_successes, prob)`, not `(mean, dispersion)`.
The conversion $p=\alpha/(\alpha+\mu)$, $r=\alpha$ must match PyMC's
$(\mu,\alpha)$ parameterization exactly, or the "known truth" would not be the
truth. Getting the parameterization right is a precondition for recovery to mean
anything.

## 4. How this generalizes

- **Project 05 (logistic)** introduced the link function; here the *log* link
  plays the same role for counts, and the "read priors on the response scale"
  habit carries over (a wide $\beta_0$ exponentiates to absurd means).
- **Hierarchical projects (09–11)** stack count or binary GLMs under a hierarchy;
  the convergence-≠-adequacy and PPC-first lessons are even more important there.
- The **model-comparison machinery** (`az.loo` / `az.compare`, Pareto-$k$
  vigilance) introduced here is reused every time a project fields $\ge 2$ models,
  including the horseshoe-vs-ridge comparison in Project 08.

The portable rule: **for count data, assume overdispersion, fit the
Negative-Binomial as the baseline, and make the Poisson justify itself with a
posterior-predictive check and an explicit LOO comparison.**

# A Guided Tour of This Book

Every chapter is built from one template, and every recurring feature appears in a fixed visual style so that you always know what you are looking at. This is the book's consistency contract. Read this page once; the features are then used without further explanation.

| Feature | Appears as | Purpose |
|---|---|---|
| **Learning Objectives** | Numbered, Bloom-tagged list at chapter open | What you will be able to *do* |
| **Chapter Outline** | Numbered section map (N.1, N.2 …) | Navigation and structure |
| **Key Terms** | Bold at first use; collected at chapter end; defined in the Glossary | Vocabulary control |
| **Concept Check** | Shaded box, mid-section | Quick formative self-test |
| **Worked Example** | Numbered box with a full solution | Modeling expert reasoning |
| **Method** | Step-numbered protocol box | A reproducible procedure |
| **Tool Box** | Sidebar naming current software + version | Keeps the text current |
| **Reality Check** | Callout with honest success rates and limits | Calibrated expectations |
| **Red Flags** | Callout listing reviewer-catching mistakes | Error prevention |
| **From the Bench** | Note from the experimentalist's view | The computation ↔ wet-lab bridge |
| **Hands-On Lab / Studio Exercise** | End-of-chapter, with platform + deliverable | Active practice |
| **Chapter Summary** | Bulleted, organized by section number | Consolidation |
| **Problem Set** | Three tiers: Review · Quantitative & Computational · Challenge | Graded assessment |
| **Further Reading** | Annotated, tiered by level | Depth on demand |

Conceptual chapters carry a **Studio Exercise**; methods chapters carry a runnable **Hands-On Lab**. Both occupy the same slot at the end of the chapter. The colored callout boxes follow a consistent code: teal for formative checks, blue for worked reasoning, green for protocols, purple for tools, amber for honest limits, and red for mistakes to avoid.
